<Section id="start" title="Get started">

A lift takes an element of yours and a menu of yours. Held for half a second, or right clicked, the element rises above everything in a modal layer, the rest of the page dimmed and blurred, and the menu opens under it, or over it with no room under. The menu is yours from the markup up: Lift places it, opens it and closes it.

<Steps>
<Step>

**Install.**

<Install pkg="@fluidkit/lift" />

</Step>
<Step>

**Have a menu, hidden**, anywhere in the page. Its items are its buttons, links and `role="menuitem"` elements.

```html
<img class="photo" src="…" alt="…" tabindex="0" />

<div class="menu" role="menu" aria-label="Photo" hidden>
  <button role="menuitem">Copy</button>
  <button role="menuitem">Share</button>
  <button role="menuitem">Delete</button>
</div>
```

</Step>
<Step>

**Create the lift** after the elements are in the DOM.

```ts
import { createLift } from "@fluidkit/lift";

const lift = createLift({
  element: document.querySelector(".photo")!,
  menu: document.querySelector(".menu")!,
  onSelect: (item) => console.log(item.textContent),
});

// On unmount:
// lift.destroy();
```

</Step>
</Steps>

</Section>

<Section id="examples" title="Examples">

### Photos

Hold a photo, or right click it. It gives a little while it's held (`data-lifting`), then lifts, and the menu opens under it, or over it near the bottom. Keep the finger down and slide onto an item to choose it as you let go; the highlight is an [Indicator](/indicator), moved by `onHighlight`. Six photos share one menu.

<Example>
<LiftExample kind="photos" />

<Fragment slot="js">

```ts
import "@fluidkit/blur/style.css";
import { createIndicator } from "@fluidkit/indicator";
import { createLift } from "@fluidkit/lift";

const menu = document.querySelector<HTMLElement>(".menu")!;
const highlight = createIndicator({ container: menu, indicator: menu.querySelector(".menu__highlight")! });

for (const photo of document.querySelectorAll<HTMLElement>(".photo")) {
  createLift({
    element: photo,
    menu,
    // The finger that lifted it slides over the items: the highlight follows
    onHighlight: (item) => highlight.to(item),
    onClose: () => highlight.to(null, { instant: true }),
  });
}
```

</Fragment>
<Fragment slot="css">

```css
.photo { border-radius: 14px; user-select: none; transition: scale 0.4s; }
/* Held: it gives a little before it lifts */
.photo[data-lifting] { scale: 0.96; }

/* `hidden` keeps it hidden until it's lifted: a display of its own would undo it */
.menu[hidden] { display: none; }
.menu { width: 230px; display: grid; padding: 6px; border-radius: 24px; }
```

</Fragment>
</Example>

<Section id="options" title="Options">

`createLift(options: LiftOptions): Lift`

| Option | Meaning |
| --- | --- |
| `element: HTMLElement` | What's held and lifted |
| `menu?: HTMLElement` | Your menu, opened beside it; hidden otherwise (`hidden`). Without one, only the element is lifted |
| `items?: string` | Its items, as a selector in the menu: `[role="menuitem"], button, a[href]` by default |
| `preview?: HTMLElement \| (element) => HTMLElement` | What's lifted instead of a copy: something live, or a bigger preview, as iOS shows. It keeps its own size, centered on the element and kept on screen; one from the page goes back where it was after |
| `delay?: number` | How long a press is held, ms: `500` by default |
| `scale?: number` | How much bigger it's lifted: `1.04` by default |
| `dim?: number` | How dark the page goes behind it, 0 to 1: `0.2` by default |
| `blur?: number` | How blurred the page goes behind it, px: `12` by default |
| `placement?: "auto" \| "below" \| "above"` | Where the menu goes: by the room there, `auto` by default |
| `spring?: SpringParams` | The spring it rises on: `defaultLiftSpring` by default. As in [core](/core#spring) |
| `onOpen?: () => void` | It's lifting |
| `onClose?: () => void` | It's closed and back in place |
| `onHighlight?: (item) => void` | The finger that lifted it is over this item, or `null` off them |
| `onSelect?: (item) => void \| boolean` | This item was chosen, by a click, a key or a finger let go on it; the menu closes after, unless it gives back `false` (a toggle in the menu, say). Never a disabled one (`:disabled`, `aria-disabled="true"`) |

</Section>

<Section id="api" title="API">

| Member | Meaning |
| --- | --- |
| `opened` | Lifted, its menu open |
| `open()` | Lifts it and opens the menu, its first item focused: for a button that opens it, say. Another lift open in the page closes at once |
| `close()` | Settles it back and closes the menu |
| `set(settings)` | Takes new options, all but `element` and `menu`, the rest kept: a component's props as they change, without a lift made again. Open, it takes them as it goes (dim, blur, callbacks) or the next time it opens |
| `destroy()` | Closes it at once and removes its listeners. Later calls do nothing |

</Section>

<Section id="react" title="React">

The same package, from `@fluidkit/lift/react` (React 18 or later): components made of parts by default, and a hook for markup of your own. They're client components (`"use client"`), rendered on the server as plain markup, the menu hidden.

```tsx
import { Lift } from "@fluidkit/lift/react";

export function Photo({ src }: { src: string }) {
  return (
    <Lift.Root onSelect={(value) => act(value)}>
      <Lift.Target render={<img className="photo" src={src} alt="" tabIndex={0} />} />
      <Lift.Menu className="menu lb" aria-label="Photo">
        <Lift.Item value="copy">Copy</Lift.Item>
        <Lift.Item value="share">Share</Lift.Item>
        <Lift.Separator />
        <Lift.Item value="delete" disabled>
          Delete
        </Lift.Item>
      </Lift.Menu>
    </Lift.Root>
  );
}
```

| Part | Renders | What it's for |
| --- | --- | --- |
| `Lift.Root` | nothing of its own | The lift: every option of `createLift` but `element`, `menu` and `preview` as props, and `open` / `defaultOpen` / `onOpenChange`. `onSelect(value, item)` is told the item chosen |
| `Lift.Target` | `div` | What's held and lifted. `data-state="open"` while it's lifted |
| `Lift.Menu` | `div role="menu" hidden` | The menu, opened beside it |
| `Lift.Item` | `button role="menuitem"` | An item. `value` is what the root's `onSelect` is given; `disabled` keeps it from being chosen (`aria-disabled`, `data-disabled`); its own `onSelect(event)` hears of it first, and `event.preventDefault()` keeps the menu open |
| `Lift.Separator` | `div role="separator"` | A line between items, passed over by the finger and the keys |
| `Lift.Preview` | `div`, hidden | Lifted instead of a copy, at its own size: something live, or bigger |

**Your elements.** Every part renders as an element of yours with `render`, as in Base UI: an element, our props merged into it (classes joined, styles and handlers both kept, refs both set), or a function of the props and the part's state.

```tsx
<Lift.Target render={<img src={src} alt="" />} />
<Lift.Target render={(props, { opened }) => <img {...props} src={opened ? large : src} alt="" />} />
```

**Controlled.** Without `open` it's its own; with `open` and `onOpenChange`, it follows the parent's state, and asks to change it when it's held, chosen from, or closed by the dim or Escape.

```tsx
const [open, setOpen] = useState(false);
<Lift.Root open={open} onOpenChange={setOpen}>…</Lift.Root>
```

**New props, the same lift.** It's made once its target is in the page and handed new props with `set()`, never made again for them; callbacks are always the latest, so arrows written in the JSX are fine. A new target or menu element makes it again.

**With an indicator.** The highlight under the finger is an [Indicator](/indicator#react), told by `onHighlight` which item it's over (`active`); the two parts become one element through `render`.

```tsx
const [pointed, setPointed] = useState<string | null>(null);

<Lift.Root onHighlight={(item) => setPointed(item?.dataset.value ?? null)} onSelect={act}>
  <Lift.Target render={<img src={src} alt="" />} />
  <Lift.Menu className="menu lb">
    <Indicator.Root active={pointed}>
      <Indicator.Thumb className="highlight" />
      <Lift.Item value="copy" render={<Indicator.Item value="copy" />}>Copy</Lift.Item>
      <Lift.Item value="share" render={<Indicator.Item value="share" />}>Share</Lift.Item>
    </Indicator.Root>
  </Lift.Menu>
</Lift.Root>
```

**The hook.** `useLift(options)` takes the same props as the root and gives refs for your elements, `opened`, `open()`, `close()` and the engine (`lift`), for markup the parts don't fit.

```tsx
const lift = useLift({ onSelect: (item) => act(item.dataset.action) });

<img ref={lift.element} src={src} alt="" />
<div ref={lift.menu} role="menu" hidden>…</div>
```

With the hook, the menu is your element and is moved into the lift's dialog while it's open: give it a parent of its own, so nothing React adds next to it then looks for it there. The parts do this for you. Unmounted while it's open, the lift is let go first and everything goes back where React expects it.

<Section id="how" title="How it works">

<Rows>
<Row>
<Cell title="The press">

Held still for `delay`, it lifts; moved more than 8px, or taken by a scroll, it doesn't. While it's held the element is marked `data-lifting` and no text on the page is selected; iOS shows no callout. A right click, or the menu key on a focused element, opens it at once. The click a long press would end in is dropped.

</Cell>
<Cell title="A copy, lifted">

What lifts is a copy of the element, every computed style written on it, so it looks the same out of its place; the element itself is hidden where it is and keeps its room. Moving it would reload a frame and stop a video, so the copy is a picture: its frames are empty boxes, not loaded again; its videos, their frame as it was; its form controls, in no form or radio group, so a checked radio in it doesn't uncheck the page's. For something live, or bigger, give `preview` an element of your own.

</Cell>
</Row>
<Row>
<Cell title="A modal layer">

They sit in a modal `<dialog>`, in the top layer, over any `overflow`, `z-index` and transform of the page's: the rest is inert, the page doesn't scroll under it by wheel, touch or keys, Escape closes it and focus goes back. The arrow keys go through the items, past disabled ones, Home and End to the ends. The dialog is the dim and the blur; the menu is moved into it while it's open and put back after, its listeners kept. One lift is open at a time in a page: another opening closes it at once.

</Cell>
<Cell title="The same finger">

The finger that lifted it can stay down and slide onto an item: each item it's over is marked `data-highlighted` and given to `onHighlight`; let go there, the item is clicked. No text is selected on the way. Let go without moving, the menu stays open for a tap. Opened by a key, its first item is focused.

</Cell>
</Row>
<Row>
<Cell title="Placement">

Under the element, or over it with no room under; on the element's side of the screen, kept 12px in from the edges. With room neither way, the element moves up for the menu, as in iOS. A window made narrower or wider closes it; a shorter one (a phone's bars, its keyboard) doesn't.

</Cell>
<Cell title="Springs">

The copy rises from where the element is drawn (given a little under the press, say) to a little bigger, the dim and the menu coming in with it. Closing, it settles exactly back on the element, wherever the element is by then (its page scrolled by a dragged scrollbar, say), before the element is shown. With reduced motion it's all at once.

</Cell>
</Row>
</Rows>

</Section>

<Section id="glass" title="With Liquid Blur">

The menu can be glass (`lb`): in the dialog it blurs the dimmed page under it. A menu's highlight can be an [Indicator](/indicator): under a mouse it follows by itself, and `onHighlight` moves it for the finger that lifted the menu.

</Section>

<Section id="support" title="Browser support">

Any browser with `<dialog>` and its `showModal()`, Pointer Events and `backdrop-filter`.

</Section>

<Section id="limitations" title="Limitations">

- A copy is a picture of the element as it was: a video in it shows its frame, a frame an empty box, a form its values as they were. Use `preview` for something live.
- A copy's pseudo-elements are dressed only if the page's rules for them still match it out of its place.
- Every computed style of every element in the copy is written on it as it lifts: a few dozen elements take a few milliseconds; hundreds take a frame or more on a phone, and the lift starts late. For a big element, give `preview` something smaller.
- The menu is moved into the dialog, out of its place: style it by its own classes, not by where it sits (`.card .menu`), and give it the custom properties it needs on itself or the root, not on an ancestor.
- So the finger that lifted it can slide onto the menu, a lifted element takes touch moves itself (a non-passive `touchmove`): a scroll that starts on it waits for the page's main thread.

</Section>
